Sign in with GitHub: what it would need

Today you paste a token. Signing in with GitHub instead would be easier to use, but it needs two things that this static site cannot hold.

What it would need

  • A GitHub OAuth App registered on an account. It has a client secret.
  • A small server that swaps the one-time code GitHub gives the browser for a token, using that secret. A static page cannot keep a secret, and GitHub's token endpoint does not allow browser requests.

Why it waits

  • It adds server code, which this site avoids by rule, and a secret to look after.
  • OAuth tokens are broader than a fine-grained token scoped to one repository, so the risk grows.
  • It is hard to undo once people rely on it. It is the owner's decision, so nothing is built until the owner says yes.

Not planned

A proxy for the git protocol. This tool reads and writes through GitHub's web API only.
